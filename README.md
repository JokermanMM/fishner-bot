# 🎣 Fishner Bot

Закрытый Telegram-бот [@fishner_bot](https://t.me/fishner_bot) для компании друзей: общая лента уловов, рекорды, статистика, фото, видео и геолокация.

Смысл, архитектура и дорожная карта ведутся в [`PROJECT.md`](PROJECT.md). Правила для всех следующих изменений — в [`AGENTS.md`](AGENTS.md).

## Что умеет MVP

- принимать друзей только по секретной пригласительной ссылке;
- пошагово добавлять улов и хранить черновик;
- принимать фото, видео, вес, длину, дату, приманку и геопозицию;
- показывать общую ленту с именами рыбаков;
- считать общие рекорды по видам рыбы;
- строить рейтинг по числу рекордов, суммарному весу, количеству уловов и видов;
- публиковать карточку в любой Telegram-чат через inline-режим;
- не показывать точные координаты в расшаренной карточке;
- показывать точку улова всем допущенным друзьям внутри бота.

## Бесплатное развёртывание

### 1. Neon Postgres

1. Создайте бесплатный проект на [Neon](https://console.neon.tech/).
2. Выберите ближайший регион в Европе.
3. Скопируйте pooled connection string вида `postgresql://...?...sslmode=require`.
4. Это значение будет секретом `DATABASE_URL` на Render.

### 2. GitHub

Создайте пустой репозиторий без README и `.gitignore`, затем добавьте его как remote для этой папки. Секреты в репозиторий не добавляются.

GitHub Actions описан в [`.github/workflows/ci.yml`](.github/workflows/ci.yml). Он проверяет проект и только после успеха вызывает Render Deploy Hook.

### 3. Render

1. В Render выберите **New → Blueprint** и подключите GitHub-репозиторий.
2. Render прочитает [`render.yaml`](render.yaml) и создаст Free Web Service.
3. При создании заполните:
   - `BOT_TOKEN` — токен BotFather;
   - `DATABASE_URL` — строку Neon;
   - `FRIEND_INVITE_CODE` — случайный код из 8–64 букв, цифр, `_` и `-`;
   - `WEBHOOK_SECRET` — случайную строку из букв и цифр длиной от 16 символов.
4. После первого деплоя откройте **Settings → Deploy Hook** и скопируйте URL.
5. В GitHub откройте **Settings → Secrets and variables → Actions** и создайте секрет `RENDER_DEPLOY_HOOK_URL`.

Render Auto-Deploy отключён: деплой вызывается GitHub Actions после тестов.

### 4. UptimeRobot

После первого успешного деплоя:

1. Создайте бесплатный **HTTP(s) monitor** в [UptimeRobot](https://uptimerobot.com/).
2. В качестве URL укажите `https://ИМЯ-СЕРВИСА.onrender.com/health`.
3. Оставьте интервал **5 минут** и метод `GET`.
4. Успешный ответ должен иметь HTTP-статус `200` и JSON `{"status":"ok"}`.

Render Free засыпает после 15 минут без входящего трафика, а бесплатный UptimeRobot проверяет адрес раз в 5 минут. Поэтому такой монитор обычно удерживает сервис активным. Это не гарантирует абсолютную доступность: Render может перезапускать Free-сервисы, а один постоянно работающий сервис расходует почти весь месячный лимит бесплатных часов.

### 5. Приглашение друзей

Ссылка имеет вид:

```text
https://t.me/fishner_bot?start=FRIEND_INVITE_CODE
```

Её нужно переслать только друзьям. После первого открытия ссылки участник остается допущенным в базе.

## Локальная проверка

Нужен Node.js 24+ и тестовая Postgres-база. Не используйте один и тот же токен одновременно в Render webhook и в локальном polling.

```bash
cp .env.example .env
npm ci
npm run dev
```

`.env` создаётся вручную и уже исключён из Git.

## Проверка кода

```bash
npm run typecheck
npm test
npm run build
```

## Ограничения Free-режима

- Без UptimeRobot Render засыпает после 15 минут без входящего трафика. Монитор `/health` раз в 5 минут обычно предотвращает сон.
- Render может перезапустить Free-сервис независимо от UptimeRobot.
- Локальные файлы Render не хранятся между деплоями. Все записи находятся в Neon.
- Медиа пока хранится в Telegram через `file_id`. Отдельная резервная копия — следующий этап.
